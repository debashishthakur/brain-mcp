# brain-mcp tool reference

Arguments marked * are required. Tool names may carry a client prefix (`mcp__brain__`, `mcp_brain_`); the part after it is what is listed here.

## Contents

- Reading: brain_identity, brain_context, brain_search, brain_read, brain_project, brain_graph, brain_recent
- Writing: brain_remember, brain_capture, brain_write, brain_edit, brain_move, brain_delete
- Also exposed: resources and prompts

## Reading

### brain_identity
Who the owner is: profile, memory notes (with How to apply lines), captured facts, skills, projects and recent focus.
- `topic`: a few words about the conversation, e.g. `"interview prep"`. Returns a smaller bundle with only the memory notes that apply. Omit for the full bundle.

### brain_context
The most relevant sections from across the vault for one question, packed under a size budget, with source note ids and a coverage verdict (good / thin / none).
- `question`*: plain words with specific nouns, ids and dates.
- `project`: restrict to one project.
- `budget_chars`: size cap for the pack (default about 18,000 characters).

### brain_search
Ranked hits with snippets and note ids, plus coverage. Keywords or a short question both work; spelling is corrected.
- `query`*: keywords.
- `project`: one project, e.g. `"Website Redesign"`.
- `type`: one of note, runbook, agent, progress, research, architecture, plan, decision, audit, spec, hub, concept.
- `topic`: notes tagged with a concept, e.g. `"OAuth"`.
- `since`: only notes modified on or after this date (`YYYY-MM-DD`).
- `limit`: number of hits.

### brain_read
One note in full, or one section, with frontmatter, topics and links.
- `note`*: note id (vault path), exact title, or `[[wikilink]]`.
- `section`: heading text, to return only that section.
- `include_connections`: keep the generated `## Connections` trailer.

### brain_project
Briefing on a project: what it is, notes grouped by type, latest progress, decisions, recent changes.
- `project`: hub name. Omit it to list every project.
- `recent_days`: window for "recent changes".

### brain_graph
Neighbours of a note, hub or concept: outgoing links, backlinks, and notes sharing its topics. On a concept it shows every project that touches it.
- `note`*: note id, title, concept name, or `[[wikilink]]`.
- `limit`: number of neighbours.

### brain_recent
Notes modified in the last N days, newest first. Hubs and concepts are left out unless asked for.
- `days`, `project`, `limit`, `include_structural`.

## Writing

Writes are confined to `Notes/` and `Captures/`; every other note is generated by the vault pipeline and read-only. Ask before writing unless the owner asked you to save (see SKILL.md, section 4).

### brain_remember
Appends one durable fact to the owner's memory file. It joins `brain_identity` immediately.
- `fact`*: one standalone sentence.
- `category`*: `user` (who they are), `feedback` (how to work with them), `project` (ongoing work), `reference` (a pointer).
- `why`: why it matters.
- `how_to_apply`: what to do differently because of it.
- `force`: store even if it looks like a duplicate. Near-duplicates are refused by default; partial overlaps are stored with a Supersedes line.

### brain_capture
Writes a new note into `Captures/` with frontmatter that links it into the graph.
- `title`*: a specific noun phrase, not a file name.
- `body`*: Markdown. Link concepts inline with `[[Concept]]` on first mention.
- `kind`: note, idea, decision, plan, log or research.
- `project`: the project hub it belongs to.
- `topics`: concept names, e.g. `["OAuth", "RAG"]`.

### brain_write
Creates a note at a chosen path under `Notes/` or `Captures/`, or replaces one with `overwrite`.
- `path`*: e.g. `"Notes/Harbor Ledger.md"`.
- `title`*, `body`* (Markdown without frontmatter or the `#` title).
- `type`: note, hub, moc, guide, runbook, plan, decision, ... A `hub` groups every note whose `project` matches its title.
- `project`, `topics`, `summary`, `order`, `overwrite`.

### brain_edit
Changes part of a note under `Notes/` or `Captures/`. Give exactly one of:
- `old_text` + `new_text`: `old_text` must occur exactly once; `new_text` may be empty.
- `section` + `content`: replaces everything under that heading, up to the next heading of the same or higher level.
- `append`: Markdown added at the end.
- Plus `note`*: note id, title or `[[wikilink]]`.

### brain_move
Moves or renames a note within `Notes/` and `Captures/`, for example to promote a capture into `Notes/`. Refuses to overwrite, and reports links that stop resolving.
- `note`*, `to`* (new vault path).

### brain_delete
Moves a note from `Notes/` or `Captures/` into `.trash/`. Nothing is erased; the result gives the path to restore from.
- `note`*.
